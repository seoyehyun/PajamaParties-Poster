# KV swap의 GPU 간섭 감소 효과와 컨텍스트 길이, A720 읽기 대역폭 (2026-11-19)

[corun-kvswap-20261119.md](corun-kvswap-20261119.md)(7K 컨텍스트, 8개 조합)의 후속이다. 같은 스크립트([corun_kvswap.py](../../code/scripts/joint/corun_kvswap.py))로 **컨텍스트 길이를 3K, 7K, 11K로 바꾸고**, 이번에는 **perf로 A720 읽기 대역폭을 같이 기록**했다(`l2d_cache_refill × 64 B`, 1초 간격). 원인에 대한 직접 증거를 얻는 것이 목적이다. 원본은 `runs/corunkv_ctx{3k,7k,11k}/`(git 제외, 보드 시계 기준 11/11 날짜)이고 요약 CSV는 [corun_kvswap_ctx_20261119_summary.csv](../csv/corun_kvswap_ctx_20261119_summary.csv)다.

## 조건

- A720 1500 MHz 고정, GPU 1000 MHz 고정. CPU 작업의 KV는 RAM 또는 KV swap. 컨텍스트마다 {ram, swap} × 2회, 구간 방식은 앞선 실험과 같다.
- 프롬프트는 C4 텍스트의 앞 13,700자(약 3,000토큰), 32,000자(약 7,000토큰), 50,000자(약 11,000토큰). 11K만 ctx 16384, 나머지는 12288.
- GPU 단독 기준: 37.7 ms/tok(세 실행에서 같음).
- 7K는 앞선 실험과 **같은 조건의 반복**이고 perf만 추가했다. 보드는 중간에 재부팅 없이 세 실행을 모두 마쳤다.

## 결과

| 컨텍스트 | KV | GPU 작업 ms/tok | **GPU 슬로다운** | **A720 읽기 대역폭** (동시 실행 중) | CPU 단독 ms/tok | 최고 온도 |
|---|---|---|---|---|---|---|
| 3K | RAM | 53.8 | +42.7% | **39.1 GB/s** | 53.5 | 60 °C |
| 3K | swap | 46.6 | +23.7% | 23.1 GB/s | 65.1 | 57 |
| 7K | RAM | 61.7 | +63.7% | **39.3 GB/s** | 76.6 | 60 |
| 7K | swap | 44.9 | +19.2% | 20.6 GB/s | 79.7 | 55 |
| 11K | RAM | 70.6 | +87.4% | **38.7 GB/s** | 101.1 | 60 |
| 11K | swap | 44.1 | +17.1% | 19.5 GB/s | 87.8 | 54 |

| 컨텍스트 | GPU 슬로다운 감소폭 (RAM → swap) | CPU 작업 속도 (swap / RAM) |
|---|---|---|
| 3K | 19%p | 1.22배(swap이 느림) |
| 7K | 44%p | 1.04배 |
| 11K | **70%p** | **0.87배(swap이 빠름)** |

7K의 이번 결과는 앞선 실험(RAM +63.4% → swap +20.0%)과 거의 같다(+63.7% → +19.2%).

## 해석

- **컨텍스트가 길수록 KV swap의 GPU 간섭 감소 효과가 커진다.** RAM KV에서는 GPU 슬로다운이 컨텍스트에 따라 늘고(+43%, +64%, +87%) swap에서는 +17~24%로 거의 일정하다.
- **원인 증거: RAM KV의 A720 대역폭은 컨텍스트와 무관하게 약 39 GB/s다.** 이 보드의 메모리 천장(앞선 보정에서 약 39~40 GB/s) 근처이고, swap에서는 약 20 GB/s로 절반이다. CPU가 DRAM을 절반만 읽으니 GPU가 쓸 수 있는 몫이 늘었다는 해석과 맞다. GPU가 얻은 유효 대역폭(`모델 크기 × tokens/s` 추정)도 RAM에서 컨텍스트가 길수록 줄고(23.7 → 20.7 → 18.1 GB/s) swap에서는 오히려 늘어난다(27.4 → 28.4 → 28.9 GB/s).
- **RAM KV는 컨텍스트가 길어도 대역폭이 늘지 못하고 속도로 나타난다.** 대역폭이 천장에 붙어 있어서 컨텍스트가 길어진 만큼 CPU가 느려지고(53 → 77 → 101 ms/tok), GPU와 나누는 몫도 줄어 GPU가 더 느려진다.
- **짧은 컨텍스트에서는 KV swap이 CPU에 손해다.** 3K에서 CPU가 22% 느리고(예측기와 I/O 오버헤드가 읽기 절감보다 큼), 7K에서 같아지고, 11K에서는 13% 빠르다. 손익분기점은 3K와 7K 사이다.
- **구간 사이 노이즈:** 같은 CPU 프로세스 안 solo 구간의 차이가 중앙값 4.6~8.9%라서 CPU 슬로다운 3~7%는 노이즈 안이다. GPU 슬로다운 차이(19~70%p)와 대역폭 차이(약 2배)는 노이즈를 훨씬 넘는다.

## 사전 계산 테이블에의 의미

동시 실행 행에서 **컨텍스트 길이가 키**가 된다: 약 3K 이하에서는 KV swap이 CPU 속도에 손해라서 이득이 작고, 7K 이상에서는 GPU 간섭이 크게 줄고 CPU 속도도 지켜진다.

| CPU 작업 컨텍스트 | 권장 KV | 근거 |
|---|---|---|
| 약 3K 이하 | 이득 작음(GPU 슬로다운 19%p 감소, CPU 22% 느려짐) | 이 문서 |
| 7K 이상 | KV swap | GPU 슬로다운 44~70%p 감소, CPU 속도 유지 또는 개선 |

## 한계

- A720 1500 MHz, GPU 1000 MHz 한 점이다. A720 기본 거버너에서는 앞선 실험에서 같은 방향이었다(7K).
- 모델 하나, 반복 2회, 컨텍스트 세 점이다. 11K는 ctx 16384이고 생성 가능 토큰이 줄어(약 1,700) 구간이 빠듯하다(4개 윈도우 모두 사용 가능으로 판정됨).
- 대역폭은 A720 코어 PMU(`l2d_cache_refill`)의 읽기 지표이고 DRAM 컨트롤러 값이 아니다. KV swap의 I/O 스레드(같은 A720 코어)의 몫이 포함된다. 쓰기는 이 지표로 잴 수 없다.
- 열은 구간별 최고 온도만 본다. 열 면적 비교는 별도 실험(열 면적 A/B)에서 한다.
