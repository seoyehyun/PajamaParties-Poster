# KV 오프로딩 8K 측정 (Orange Pi 6 Plus, 2026-11-05 ~ 06)

KV cache를 저장장치에 두었을 때의 decode 속도를 저장장치 두 종류(microSD, NVMe)에서 쟀다. 설정마다 1회만 실행해서 편차는 모른다.

| 파일 | 내용 |
|---|---|
| `kvswap_8k_microsd_20261105.csv` | microSD (`sda`, USB 2.0 리더 경유) 결과. `summarize_stage1.py` 출력 |
| `kvswap_8k_nvme_20261106.csv` | NVMe SSD (`nvme0n1`) 결과 |

## 조건

| 항목 | 값 |
|---|---|
| 모델 | Qwen3-1.7B Q4_K_M, `-fa on`, temp 0, seed 1 |
| 입력 | `data/prompt_300.txt`를 25번 이어 붙인 프롬프트 (7,533토큰), `-c 8192` |
| 생성 | 64토큰 (B3 평가는 32토큰). microSD의 B1은 너무 느려 16토큰 |
| 코어 | cpu6-9 (A720), 4스레드, 주파수 고정 안 함 (`schedutil`) |
| 빌드 | `931351ea5` + 패치 01~04, armv9.2 빌드 |
| KV I/O | direct I/O (`O_DIRECT`), 메모리 제한 없음, 리더 4스레드 |
| 선택 | G=8, W=256, sink 4그룹, M=50 그룹 (400셀) |
| 예측기 | `make_kvswap_adapter.py`로 만든 r=128 (σ=8) 어댑터. C4 validation 16개 × 2,048토큰 |

설정 이름은 다음과 같다.

| 이름 | KV 위치 | 읽는 셀 |
|---|---|---|
| B0 base | RAM | 전부 |
| B1 file | 저장장치 | 매 토큰 전부 |
| B2 | 저장장치 | 1단계 고정 규칙: sink + 균등 간격 M그룹 + 최근 W |
| B3 | 저장장치 | 2단계 예측기: sink + 예측한 top-M 그룹 + 최근 W |

## decode 속도

| 설정 | microSD ms/token | NVMe ms/token |
|---|---|---|
| B0 base (RAM) | 87 | 87 |
| B1 전체 읽기 | 28,635 | **410** |
| B2 균등 선택 | 2,843 (프리페치 on), 2,915 (off) | **184** |
| B3 예측기 | 측정 안 함 | **173** |

prefill은 모든 설정에서 약 10 t/s(7,533토큰에 약 12.5분)다. 긴 컨텍스트에서 CPU flash attention이 느린 탓이며 오프로딩과는 관계없다.

## NVMe I/O 지표

| 설정 | 읽은 양 | 읽기 요청 | I/O 대기 합계 | 디스크 util | %iowait |
|---|---|---|---|---|---|
| B1 | 51.1 GB | 53,760 | 5.6 s | 72% | 19.6 |
| B2 | 2.9 GB | 175,616 | 4.5 s | 51% | 13.5 |
| B3 | 3.0 GB | 125,970 | 3.4 s | 49% | 14.6 |

- microSD에서는 B1, B2 모두 디스크 util이 93~96%로 포화였다. NVMe에서는 B2, B3의 util이 50% 안팎이고 I/O 대기가 토큰당 50~70 ms라서, storage만의 병목이 아니다. 계산, 콜백 오버헤드(그래프 분할), 쓰기가 섞여 있다.
- 예측기는 서로 붙은 그룹을 고르는 경우가 많아 인접 요청이 합쳐진다. 읽는 양은 B2와 비슷하지만 요청 수가 28% 적고 대기가 25% 짧다. B2 대비 6% 빠른 것은 1회 측정이라 반복 확인이 필요하다.
- 예측 계산은 8K에서 10.9 ms/step(28개 레이어 합)이다.

## 예측 정확도 (8K, 유지된 어텐션 질량)

`LLAMA_KV_PRED_EVAL=1`로 실제 Q의 softmax 어텐션을 계산해, 선택한 셀이 어텐션 질량을 얼마나 덮는지 쟀다(헤드, 레이어, 스텝 평균). 오라클은 같은 M에서 질량이 가장 큰 그룹을 고른 이론 상한이다.

| sink + 최근 창만 | B2 균등 | B3 예측기 | 오라클 |
|---|---|---|---|
| 0.893 | 0.916 | **0.937** | 0.944 |

- 그룹 recall(예측 그룹과 오라클 그룹이 겹치는 비율)은 0.61이다. 1.2K 컨텍스트 시험에서는 0.78이었다.
- 약한 곳은 앞쪽 레이어다. 레이어 1은 recall 0.13(질량 0.681, 오라클 0.739), 레이어 0은 0.36, 레이어 2는 0.57이다. 레이어 1은 레이어 0의 입력으로 예측하기 때문으로 보인다. 논문은 레이어 0, 1을 예측하지 않고 정확한 값을 쓴다.

## 해석할 때 주의할 점

- 설정마다 1회 실행이다.
- 프롬프트가 무작위 단어라 어텐션 패턴이 실제 텍스트와 다를 수 있다. 실제 텍스트 품질은 [kvswap-niah.md](kvswap-niah.md)에 있다.
- 주파수를 고정하지 않았다. 측정 중 최고 온도는 57 °C로 A720 온도 존의 60 °C 트립보다 낮다.
- microSD와 NVMe 측정 사이에 보드가 두 번 재부팅됐다(원인 미상). 표의 값은 모두 재부팅 없이 끝난 실행이다.
- 전력을 재지 않았다.

## 추가: 레이어 0, 1을 자기 입력으로 예측 (2026-11-07)

위 결과의 예측기는 레이어 1부터 이전 레이어 입력으로 미리 예측했다. 논문처럼 레이어 0, 1은 자기 입력(정확한 Q)으로 고르도록 바꿨다(`LLAMA_KV_PRED_EXACT`, 기본 2). 이 두 레이어는 읽기가 계산과 겹치지 않는다. 4K 프롬프트(3.9K토큰), M=50, `-fa off`, RAM에서 32토큰 생성으로 비교했다.

| | 전체 질량 | 레이어 1 질량 | 레이어 1 recall | 레이어 0 recall |
|---|---|---|---|---|
| 이전 (`EXACT=1`) | 0.9430 | 0.690 | 0.20 | 0.15 |
| 변경 (`EXACT=2`) | **0.9448** | **0.728** | **0.37** | 0.16 |
| 오라클 | 0.953 | 0.758 | | |

- 레이어 1은 좋아졌지만 전체 평균에는 +0.2%p로 작다.
- 레이어 0은 정확한 Q를 써도 recall이 0.16이다. 입력이 아니라 저랭크 압축 자체가 이 레이어에서 약하다는 뜻이다. 레이어 0만 전체 차원 K를 RAM에 두는 방법이 남아 있다.
