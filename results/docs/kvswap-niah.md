# KVSwap 선택 방식의 NIAH 품질 (Orange Pi 6 Plus, 2026-11-07)

긴 실제 텍스트 속 한 문장(바늘)을 찾아 답하게 해서, KV를 일부만 읽는 선택 방식이 답을 망가뜨리는지 봤다. `scripts/kvswap/niah_kvswap.py`로 돌렸고 원본은 `kvswap_niah_4k_20261107.csv`다.

## 조건

| 항목 | 값 |
|---|---|
| 모델 | Qwen3-1.7B Q4_K_M, temp 0, `-no-cnv`(채팅 템플릿 없이 이어 쓰기), `-fa off` |
| 건초더미 | C4 `en` train 분할 문서, 16,000자로 자름 (프롬프트 3,482~4,415토큰), `-c 6144` |
| 바늘 | `The secret passcode for <이름> is <7자리 숫자>.` 깊이 0.1, 0.3, 0.5, 0.7, 0.9에 3문항씩, 15문항 |
| 질문 | 끝에 `Question: ... what is the secret passcode for <이름>?` / `Answer: The secret passcode for <이름> is` |
| 채점 | 생성한 12토큰 안에 7자리 숫자가 그대로 있으면 정답 |
| KV | RAM에 둠 (오프로딩 파일 없음). 선택 품질은 KV 위치와 무관하다 |
| 선택 예산 | M=16그룹 × G=8 = 128셀, 최근 창 W=128, sink 4그룹(32셀). 프롬프트의 약 7~8% |
| 어댑터 | `make_kvswap_adapter.py`, C4 validation 16개 × 2,048토큰. r=128(σ=8), r=32(σ=32) |
| 빌드 | 패치 01~04. 이때의 04는 레이어 1부터 look-ahead 예측(`LLAMA_KV_PRED_EXACT=1`과 같은 동작) |

## 결과

| 설정 | 정답 | 깊이별 |
|---|---|---|
| 전체 어텐션 | **15/15** | 모든 깊이 3/3 |
| 1단계 균등 선택 | **0/15** | 모든 깊이 0/3 |
| 예측기 r=128 | **15/15** | 모든 깊이 3/3 |
| 예측기 r=32 | **15/15** | 모든 깊이 3/3 |

- 균등 선택은 `1234`, `123456`, `2001`, `555` 같은 숫자를 지어냈다. 첫 숫자가 맞은 경우도 6/15뿐이다.
- 첫 생성 토큰(prefill에서 나옴, 전체 어텐션)은 숫자 앞의 공백이다. 숫자는 한 자리씩 토큰이 되므로 7자리 모두 선택 상태의 decode에서 나왔다.
- 압축비를 32배로 올려도(r=32) 바늘을 모두 찾았다.

## 해석할 때 주의할 점

- 15문항, 한 길이(약 4K)뿐이다. 계획서의 완료 기준(4K~32K, 25문항)보다 작다.
- 정답률이 0% 또는 100%로 갈려 예측기 r=128과 r=32의 차이는 보이지 않는다. 차이를 보려면 예산을 더 줄이거나(M=4, 8) 컨텍스트를 늘려야 한다.
- 바늘 문장이 주변 텍스트와 성격이 달라(숫자, 고유명) 어텐션이 몰리기 쉽다. 여러 사실을 묻는 과제나 요약 같은 과제의 품질은 따로 봐야 한다.
- 속도와 무관한 평가라 `-fa off`로 돌렸다. 오프로딩 측정은 `-fa on`이다. 마스크 의미는 같다.
