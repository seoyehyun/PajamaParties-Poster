## 선택 규칙

"최적"은 열이 가장 낮은 설정이다(kvswap-x-sweep-plan.md의 정의). 칸마다 아래를 **모두** 만족하는 후보 중 열 면적(존 8, 시나리오 기준선 대비)이 가장 낮은 것을 골랐다.

- TPOT ≤ 기준선 1.10배, TTFT ≤ 1.10배, 동시 실행은 두 작업의 TPOT 모두 ≤ 1.10배
- 품질 ≥ 0.93(KV swap은 0.937)
- 열 이득이 노이즈 폭(max(5%, 반복 간 폭의 2배))보다 커야 "이득", 아니면 "차이 없음"

만족하는 후보가 없으면 칸에 "없음"을 쓰고 가장 가까운 후보와 위반 항목을 적었다. 열 값은 모두 **기준선 대비 비율**(1.00 = 기본 거버너)이다.

## 표 1. GPU 지배 (GPU 전용 decode) — 키: GPU 주파수

기준선은 GPU, A720 모두 기본(`gnaive`). 나머지 자원은 A720(기본 또는 800 MHz)이다.

| GPU 주파수 | 최적 A720 | 열 | TPOT | 판정 |
|---|---|---|---|---|
| 1000 MHz | 기본 | 0.99 | 1.00 | 통과, 이득 없음(노이즈 이내). A720 800은 열 1.06 |
| 800 MHz | (없음) | 1.09 (A720 기본), 1.10 (A720 800) | 1.20 | 속도 위반, 열도 증가 |
| 600 MHz | (없음) | 1.13 (A720 기본), 1.17 (A720 800) | 1.57 | 속도 위반, 열도 증가 |
| 350 MHz | (없음) | 1.44 (A720 기본), 1.49 (A720 800) | 2.61 | 속도 위반, 열도 증가 |
| 기본 거버너 | 기본 | 1.00 | 1.00 | 기준선 |

- **모든 GPU 주파수에서 A720 기본이 800보다 열이 낮거나 같다.** GPU를 낮춰서 느려진 만큼 호스트 쪽이 더 오래 일해서 열이 늘어난다. 이 시나리오의 A720 칸은 "건드리지 않는다"가 답이다.

## 표 2. CPU와 GPU 동시 실행 — 키: GPU 주파수, 그리고 키: A720 주파수

기준선은 `co_gdef_cdef`(GPU 작업 1개 + CPU 작업 4개, 둘 다 기본). 격자는 GPU {600, 1000} × A720 {기본, 1500, 800}의 6칸이다. 칸 안의 값은 열 / GPU 작업 TPOT / CPU 작업 TPOT이다.

| | A720 기본 | A720 1500 | A720 800 |
|---|---|---|---|
| **GPU 1000** | 1.01 / 1.00 / 1.01 | **0.74 / 0.83 / 1.12** | 0.81 / 0.77 / 2.46 |
| **GPU 600** | 1.02 / 1.42 / 0.99 | 0.75 / 1.22 / 1.11 | 0.83 / 1.20 / 2.47 |
| GPU 350, 800 | 미측정 | 미측정 | 미측정 |

**키가 GPU 주파수일 때(A720을 고른다):**

| GPU 주파수 | 최적 A720 | 열 | 비고 |
|---|---|---|---|
| 1000 MHz | 1500 | 0.74 (전체 존 평균 0.88) | CPU 작업 TPOT 1.12배로 제약 1.10을 0.02 초과. **제약을 1.15로 두면 통과** |
| 600 MHz | (없음) | 0.75 (A720 1500) | GPU 작업 TPOT 1.22배로 위반 |
| 350, 800 MHz | 미측정 | | |

**키가 A720 주파수일 때(GPU를 고른다):**

| A720 주파수 | 최적 GPU | 열 | 비고 |
|---|---|---|---|
| 기본 | 1000 | 1.01 | 이득 없음, GPU 600은 속도 위반(1.42배) |
| 1500 | 1000 | 0.74 | 위와 같은 CPU 작업 1.12배 경계. GPU 600은 열 0.75에 GPU 1.22배라 속도 위반 |
| 800 | (없음) | 0.81 (GPU 1000) | CPU 작업 TPOT 2.46배 위반 |
| 1200, 1800, 2200 등 | 미측정 | | |

두 방향 모두 **GPU는 1000 MHz(최대)**가 답이고, 열을 줄이는 요인은 A720 1500이다.

## 표 3. CPU 지배 (CPU 전용 decode, 7K 컨텍스트) — 키: A720 주파수

나머지 자원은 KV cache 저장 위치(RAM, 디스크 swap)와 단계별 주파수(prefill 기본 + decode만 낮춤)다. GPU는 쓰지 않는다. 열, TPOT, TTFT는 기준선(RAM, A720 기본) 대비다.

| A720 설정 | KV | 열 | TPOT | TTFT | 판정 |
|---|---|---|---|---|---|
| 기본 | RAM | 1.00 | 1.00 | 1.00 | 기준선 |
| 기본 | swap | 0.87~0.90 | 0.90 | 1.04 | 통과(품질 0.937) |
| decode만 1500 (prefill 기본) | RAM | 0.87 | 1.05 | 1.00 | **통과, 이득** |
| decode만 1500 | swap | 0.90 (11/14, 반복 1회). 11/21 재측정(n=2): swap 기본 대비 전체 0.95, 첫 토큰 이후 0.78~0.84 | 1.02~1.03 | 1.04 | **통과, 이득(첫 토큰 이후)**. 11/14의 "이득 없음"은 1회 측정 |
| 전체 1500 | RAM | 0.71 | 1.05 | 1.51 | TTFT 위반 |
| 전체 1500 | swap | 0.61 | 1.03 | 1.55 | TTFT 위반 |
| 전체 1200 | RAM, swap | 0.71, 0.65 | 1.15, 1.17 | 1.84, 1.89 | TPOT, TTFT 위반 |

- 열이 가장 낮은 건 전체 1500이지만 prefill이 1.5배 길어져서(TTFT) 속도 조건을 넘는다. 조건을 지키면서 가장 낮은 것은 **decode만 1500(RAM) 0.87**과 **KV swap(기본 주파수) 0.87~0.90**이다. 11/14에는 둘을 합쳐도 더 낮아지지 않았지만(1회), 11/21 재측정(n=2)에서 KV swap + decode만 1500은 swap 기본 대비 decode 구간 열 0.75, 첫 토큰 이후 0.78~0.84로 분명히 낮았다. 전체 요청 열은 0.95로 차이가 작은데, 두 설정에 공통인 prefill이 열의 약 70%라 차이가 묻히기 때문이다. 그래서 KV swap일 때도 decode는 1500이 답이다.
- 이 표의 키는 "A720 요청 주파수"다. 1800, 2200처럼 일부 코어가 요청과 다르게 도는 값은 측정하지 않았다.

## 비어 있는 칸과 한계

- **GPU 800, 350 MHz의 동시 실행**, **A720 1200, 1800, 2200 등 다른 주파수**, **GPU 전용에서 A720 1500**(800만 측정)은 미측정이다. 지금 테이블은 격자가 성긴 대략의 지도다.
- CPU 전용(표 3)에는 GPU 축이 없고 GPU 시나리오(표 1, 2)에는 KV swap이 없다. KV swap은 GPU 경로에서 세그폴트가 나서 넣지 못했다. 따라서 **KV swap, GPU, A720을 모두 합친 칸은 만들 수 없다.**
- 표 1, 2는 컨텍스트 4096(프롬프트 728 + 생성 약 1000), 표 3은 7K라 칸 사이의 절대 열값은 비교할 수 없고 **기준선 대비 비율만** 쓴다.
- 열 면적은 에너지의 대리 지표이고 전력 센서가 없다. 설정당 반복은 2회(일부 1회)라 5~15% 노이즈가 있다. 모델과 요청이 하나다.
- "동시 실행"의 CPU 작업 제약(1.10배)이 결과를 가른다. 0.02 차이로 통과 여부가 갈리는 칸이 있다.
- 부분 오프로드(레이어 분할)는 이 보드에서 실행이 느려서 테이블에 넣지 못했다(partial-offload-experiment-plan.md 6절).
