# CPU 작업의 KV 위치와 A720 주파수가 동시 실행의 열 면적에 미치는 영향 (Orange Pi 6 Plus, 2026-11-19)

[corun-kvswap-20261119.md](corun-kvswap-20261119.md)와 [corun-kvswap-ctx-20261119.md](corun-kvswap-ctx-20261119.md)에서 KV swap이 GPU 간섭을 줄이는 것을 속도와 온도로 보았다. 이 실험은 같은 질문을 **열 면적(프로젝트에서 정한 "최적" 기준, 에너지 대리 지표)** 으로 잰다. 스크립트는 [thermal_ab.py](../../code/scripts/joint/thermal_ab.py)의 새 설정 `ck_<ram|swap>_g<GPU>_c<A720>`이다. 원본은 `runs/ck_heat/`(git 제외, 보드 시계 기준 11/11 날짜)다.

| 파일 | 내용 |
|---|---|
| `thermal_ab_ck_20261119_summary.csv` | 스크립트 리포트(설정별 평균, 판정) |
| `thermal_ab_ck_20261119_runs.csv` | 8회 각각의 속도, 열 면적(존 8, 전체 존 평균, 기준선 대비) |

## 조건

- CPU 작업 하나(Qwen3-1.7B Q4_K_M, 약 7,000토큰 프롬프트, **3,000토큰 생성**, A720 8스레드)가 prefill 후 decode한다. 첫 토큰이 나오면 **GPU 작업**(Vulkan, `-ngl 99`, 호스트 스레드 1개를 A520에, 짧은 프롬프트, 3,000토큰 생성)이 시작된다. 작업량(약 6,000토큰)은 모든 설정에서 같다.
- 설정 4개 × 2라운드(라운드마다 순서를 돌림), 모두 식는 꼬리까지 측정됐다. 기준선 `ck_ram_gdef_cdef`는 RAM KV, GPU와 A720 모두 기본 거버너. 나머지는 GPU 1000 MHz 고정이고 A720은 기본 또는 1500 MHz **고정(prefill 포함 요청 전체)**.
- 열 면적은 기준선에서 가장 뜨거운 존 8로 쟀다. 두 가지를 낸다. **전체 요청**(prefill + decode + 꼬리)과 **첫 토큰 이후**(`heat_post`: 모든 설정에 공통인 prefill 구간을 뺀 것).
- 판정은 앞선 열 A/B와 같다: 열 이득 > 노이즈 폭, CPU 작업과 GPU 작업의 TPOT ≤ 1.10배, TTFT ≤ 1.10배, 품질 ≥ 0.93(KV swap은 0.945로 입력).

## 결과 (기준선 대비)

| 설정 | CPU 작업 TPOT | GPU 작업 TPOT | TTFT(prefill) | 전체 소요 | **열, 전체 요청** (존 8, 두 회차 범위) | **열, 첫 토큰 이후** (존 8) | 전체 존 평균 (전체 / 첫 토큰 이후) | 최고 온도 |
|---|---|---|---|---|---|---|---|---|
| `ck_ram_gdef_cdef` (기준선) | 81.2 ms | 75.6 ms | 333 s | 577 s | 1.00 (0.93~1.07) | 1.00 (0.92~1.08) | 1.00 / 1.00 | 72 °C |
| `ck_ram_g1000_c1500` | 86.5 (1.07) | 71.0 (0.94) | **502 s (1.51)** | 1.32 | 0.71 (0.68~0.75) | 0.72 (0.69~0.75) | 0.81 / 0.82 | 61 |
| `ck_swap_g1000_cdef` | **67.8 (0.83)** | **60.7 (0.80)** | 347 s (1.04) | 0.95 | 0.90 (0.89~0.92) | **0.76 (0.74~0.78)** | 0.90 / 0.78 | 67 |
| `ck_swap_g1000_c1500` | 78.2 (0.96) | **58.5 (0.77)** | **518 s (1.55)** | 1.30 | **0.65 (0.63~0.67)** | **0.58 (0.56~0.60)** | **0.76 / 0.68** | 59 |

스크립트 판정: `ck_ram_g1000_c1500`, `ck_swap_g1000_c1500`은 "heat lower but TTFT too long", `ck_swap_g1000_cdef`는 "no clear gain (within noise)"다. 기준선의 두 회차 차이가 커서(0.93과 1.07) 노이즈 폭이 14%로 잡혔기 때문이다. 두 회차 범위끼리는 겹치지 않는다.

## 해석

- **KV swap만 쓰면(A720 기본) 전체 요청 열은 0.90배, 첫 토큰 이후는 0.76배다.** prefill이 전체의 큰 몫이고 두 설정에서 같아서 전체 요청 값이 희석된다. decode와 동시 실행 구간만 보면 열이 24% 낮다. 속도는 CPU 작업 0.83배, GPU 작업 0.80배로 **둘 다 빨라진다**. 앞선 속도 실험(GPU 슬로다운 감소)이 열에서도 이어진다.
- **A720 1500 고정은 열이 가장 많이 줄지만 TTFT가 1.5배가 된다.** prefill도 1500 MHz에서 돌아서 502~518초가 걸린다(기준선 333초). TTFT ≤ 1.10배 제약에 걸려 단독으로는 통과하지 못한다. 앞선 CPU 전용 실험에서 "decode만 1500"으로 이 문제를 풀었다(열 0.87배, TTFT 1.00배). 이번 실험에는 그 단계별 설정이 없다.
- **KV swap과 A720 1500이 더해진다.** 첫 토큰 이후 열이 1500만 쓸 때 0.72배, swap만 쓸 때 0.76배, 둘 다 쓰면 **0.58배**(두 회차 범위가 서로 겹치지 않음). 앞선 열 A/B에서 본 "두 효과가 곱으로 합쳐진다"(0.76 × 0.72 ≈ 0.55 대 측정 0.58)가 동시 실행에서도 맞다.
- **GPU 작업도 항상 이득이다.** GPU 작업 TPOT이 swap에서 0.80배(A720 기본), 0.77배(A720 1500)다. A720 1500만 쓸 때는 0.94배.
- 최고 온도: 72 → 67(swap) → 61(1500) → 59 °C(둘 다).

## 사전 계산 테이블에의 의미

[precomputed-table.md](precomputed-table.md)의 동시 실행 행(CPU 작업이 긴 컨텍스트)이 열 면적으로 채워진다.

| 조합 | 열(첫 토큰 이후) | 열(전체 요청) | 속도 |
|---|---|---|---|
| CPU KV swap + A720 기본 + GPU 1000 | 0.76 | 0.90 (노이즈 폭 안) | CPU 0.83, GPU 0.80, TTFT 1.04 → **제약 모두 통과** |
| CPU KV swap + A720 1500(전체 고정) + GPU 1000 | 0.58 | 0.65 | TTFT 1.55로 위반 |
| (미측정) CPU KV swap + decode만 A720 1500 + GPU 1000 | 0.58보다 낮지 않을 것으로 예상 | | TTFT 유지 예상 |

현재 측정만으로는 **"CPU KV swap + A720 기본 + GPU 1000"이 속도 제약을 모두 지키는 열 최저 조합**이다. decode만 1500으로 낮추는 설정(`kvphase` 계열의 동시 실행판)은 아직 안 재서, 그 조합이 TTFT를 지키면서 열을 더 줄이는지는 미확인이다.

## 한계

- 열 면적 비교의 노이즈 폭이 크다. 기준선의 두 회차가 0.93, 1.07이다(전체 존 평균은 0.90, 1.10). 같은 설정의 두 회차 사이는 0.01~0.07이다. 설정 간 차이 중 swap 단독의 **전체 요청 값 0.90은 노이즈 폭 안**이고, 첫 토큰 이후 값 0.76과 두 가지를 모두 더한 값은 범위가 겹치지 않는다.
- **첫 토큰 이후 열(heat_post)은 앞 단계의 온도 상태를 물려받는다.** A720 1500 고정 설정은 prefill이 더 낮은 온도에서 끝나서 이 값이 유리하게 나온다. decode만 1500으로 낮추는 설정과 직접 비교할 수 없다.
- 모델 하나, 컨텍스트 하나(7K), GPU 1000 MHz 한 점, 반복 2회다. 열 면적은 전력 센서가 없는 대리 지표다.
- GPU 작업은 짧은 프롬프트, 3,000토큰이다. GPU 작업이 CPU decode보다 약 15~50초 먼저 끝나서(설정마다 다름, A720 1500 RAM이 가장 큼) 마지막 구간은 CPU 작업만 돈다.
- KV swap은 CPU 작업에만 있고 GPU 작업과 같은 프로세스에서는 쓰지 못한다(세그폴트).

## 다음

1. CPU decode 구간만 A720 1500으로 낮추는 동시 실행 설정(`kvphase` + GPU 작업)을 추가한다. TTFT를 지키면서 열이 0.58배에 가까워지는지가 핵심 질문이다.
2. A720 800 MHz는 CPU 작업이 느려지는 것이 확인됐으니 제외하고, 1200~1800 사이 점을 하나 더 본다(요청과 실제 주파수가 다른 점은 CPPC로 확인).
