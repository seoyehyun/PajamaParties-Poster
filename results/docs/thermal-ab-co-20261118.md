# CPU 작업과 GPU 작업 동시 실행(S3)의 GPU, A720 주파수 열 A/B (Orange Pi 6 Plus, 2026-11-18)

gpu-axis-experiment-plan.md의 **S3(동시 실행)** 결과다. 한 모델을 레이어 단위로 나누는 부분 오프로드는 이 보드에서 너무 느려서 실험하지 못했고(partial-offload-experiment-plan.md 6절), 그 대신 CPU 작업과 GPU 작업을 **별개 프로세스로 동시에** 돌렸다. 스크립트는 [thermal_ab.py](../../code/scripts/joint/thermal_ab.py)(`co_g<GPU|def>_c<A720|def>` 설정). 원본은 `runs/thermal_co_s3/`(git 제외, 보드 시계 기준 11/11 날짜).

## 조건

- GPU 작업 1개: Vulkan 빌드, `-ngl 99`, 호스트 스레드 1개를 A520 cpu2에. 프롬프트 728토큰 + 생성 999토큰, ctx 4096. 동시에 CPU 작업: CPU 빌드(KV swap 패치는 꺼짐), A720 8스레드, **같은 요청을 4번 연달아**. 총 4,995토큰(999 + 999 × 4)이다. 작업량은 모든 설정에서 같다.
- 설정 7개 × 2라운드 = 14회, 라운드마다 순서를 돌렸다. 기준 구간(45초)과 식는 꼬리는 기본 거버너 상태이고 14회 모두 꼬리가 완료됐다.
- `co_gdef_cdef`가 기준선(GPU, A720 모두 기본). `co_g<G>_c<C>`는 GPU를 G MHz, A720 4개 정책을 C MHz로 고정(`def`는 기본). 열 면적은 기준선에서 가장 뜨거운 **존 8**(토큰당 1.70 °C·s)로 쟀고, 전체 존 평균도 같이 봤다.
- 판정: 열 이득 > 노이즈 폭, **GPU 작업과 CPU 작업의 TPOT이 모두 기준선의 1.10배 이하**, GPU 작업의 prefill ≤ 1.10배. 표의 "TPOT, prefill"은 GPU 작업 기준이다.

## 해석

- **A720 주파수를 낮추면 열이 줄고 GPU 작업은 오히려 빨라진다.** A720을 1500 MHz로 고정하면 열 면적이 0.74배(전체 존 평균 0.88배), GPU 작업은 TPOT 0.83배로 빨라진다. 동시에 도는 CPU 작업이 메모리 대역폭을 덜 가져가서 GPU 간섭이 줄어든 것으로 보인다(앞선 co-run 스윕에서 GPU가 CPU 주파수에 영향을 받은 것과 같은 방향이다).
- **하지만 CPU 작업이 느려진다.** 1500 MHz에서 CPU 작업 TPOT 1.12배(속도 제약 1.10배를 0.02 넘음), 전체 소요 시간 1.22배(CPU 작업이 오래 걸려서 CPU 작업 4개가 끝날 때까지가 전체 시간이다)다. 800 MHz는 CPU 작업이 2.46배로 느려서 후보가 못 된다.
- **GPU 600 MHz는 도움이 되지 않았다.** GPU 작업이 1.2~1.4배 느려지고(속도 제약 위반) 열도 같은 A720 설정의 GPU 1000 MHz 설정보다 낮지 않았다(0.75배 대 0.74배, 1.02배 대 1.01배). GPU 전용 실험의 결과(GPU를 낮추면 열이 늘어남)와 일치한다.
- **판정이 "TOO SLOW"인 이유는 CPU 작업 쪽 속도 제약 1.10배를 0.02 차이로 넘었기 때문이다.** 제약을 1.15배로 두면 `co_g1000_c1500`이 IMPROVED가 된다. 이 기준선의 위치는 임의의 값이라, 결론은 "후보는 GPU 최대 + A720 1500 MHz이고, 제약을 어떻게 잡느냐에 따라 통과 여부가 갈린다"이다.
- **A720 800 MHz 고정은 존 8 기준으로만 열이 낮아 보인다**(0.81배). 전체 존 평균으로는 1.00배라 이득이 없고, 소요 시간이 2.4배 길어진다.

## 사전 계산 테이블에의 의미 (세 시나리오 합침)

| 지배 자원 상태 | 열 최저이면서 속도를 지키는 조합 | 열 | 근거 |
|---|---|---|---|
| CPU 지배(CPU 전용 decode) | prefill 기본 + decode 중 A720 1500 MHz | 0.87배(TTFT 1.00배) | [thermal-ab-phase-20261114.md](thermal-ab-phase-20261114.md) |
| GPU 지배(GPU 단독) | GPU 최대, A720 기본 | 0.99배(이득 없음) | [thermal-ab-gpu-20261118.md](thermal-ab-gpu-20261118.md) |
| CPU와 GPU 동시 | GPU 최대(1000) + A720 1500 MHz | 0.74배(존 8), 0.88배(전체), GPU 작업 0.83배, CPU 작업 1.12배 | 이 문서. CPU 작업 속도 제약을 1.12배로 넘음 |

- 세 경우 모두 **GPU는 최대 주파수**가 열 최저와 속도에 유리했고, **A720은 지배 자원이 아닐 때 낮추는 것**(1500 MHz)이 열을 줄였다. 지배 자원의 주파수를 키로 보면 "지배 자원은 높게, 나머지는 낮추되 속도 제약 안에서"라는 규칙이다.
- 부분 오프로드(레이어 분할)는 이 스택에서 실행이 불가능했다는 것도 같이 기록해야 한다.

## 한계

- 모델 하나, 요청 하나이고 설정당 반복 2회다. 열 면적은 에너지의 대리 지표이고 전력 센서가 없다.
- 작업량(GPU 1개 + CPU 4개)은 두 작업이 비슷한 시간 동안 겹치도록 고른 값이다. 비율이 달라지면 결과도 달라진다. 설정에 따라 두 작업이 끝나는 시점이 달라서(A720 1500에서는 CPU 작업이 늦게 끝남) 요청 후반에는 한쪽만 돌아간다.
- 열 면적은 가장 뜨거운 존(8, CPU 쪽 존) 기준이다. 전체 존 평균은 이득이 더 작다(0.88배).
- A720 주파수는 요청값이고, 800과 1500은 4개 정책에서 실제값과 일치하는 점이다. GPU는 devfreq `cur_freq` 기준이다.
- KV swap은 넣지 못했다(GPU 경로와 호환되지 않음).
- "CPU 작업 TPOT ≤ 1.10배" 같은 속도 제약값이 결과를 좌우한다. 서비스 요구에 맞게 정해야 한다.

## 다음 실험 후보

1. A720을 1500보다 약간 높은 점(예: 1800)에서 CPU 작업 TPOT 제약을 지키는 지점을 찾는다. 단 1800은 일부 코어가 1900으로 돌아서 설정 해석에 주의가 필요하다.
2. CPU 작업과 GPU 작업의 비율(CPU 요청 수)을 바꿔서 지배 자원이 바뀌는지 본다.
3. 전력 측정이 가능해지면 열 면적과 비교한다.
